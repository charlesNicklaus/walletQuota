# 持续抓取并自动导入 PostgreSQL

用户要求启动脚本用于长期抓取，并确认每轮自动写入已经创建的 PostgreSQL 数据库。沿用现有启动立即查询、IST 每小时 `:00/:20/:40`、禁止重叠和历史保留规则。

`start.sh` 从自身目录读取 `.env`，默认通过 nohup 启动脱离终端的 Python 定时器，日志私有，显示实际 Python PID；前台模式支持 Ctrl+C。可用的 caffeinate 随采集进程存活，后台不引入额外服务管理框架。

定时器的 `--postgres` 模式调用独立单轮流水线，复用现有三个 Provider 与 Hoyo 只读收集器。每个渠道独立失败，标准报告先写到本地，失败及不完整渠道不计入可信总计。默认手工 CLI 与前台定时模式保持原有行为。

每轮报告生成精确 SQL 和私有待导入标记，再通过 psql 导入。数据库连接参数只经过环境变量，错误输出不原样进入日志。失败保留待导入批次，下一轮在完成新抓取后重试；成功只重命名标记，不删除历史。确定性批次 ID 保证重试不重复插入。

验证使用假 Provider、假 psql 和短生命周期假进程，不在开发机启动真实长期采集。覆盖多渠道隔离、SQL 文件完整性、数据库失败恢复、配置转发、前后台启动、日志权限和现有调度锁。
