# 独立定时查询与 IST 日终清理设计

日期：2026-08-13

## 目标

为 walletQuota 增加完全独立于 Codex、cron 和 `launchd` 的 Python 常驻调度器。由用户手动启动进程；进程每 20 分钟查询全部已启用渠道并保存报告，在 IST 日期切换后删除所有早于当天、由 walletQuota 导出的报告。

现有手动查询入口 `python3 wallet_quota.py --verbose` 保持不变。手动报告与定时报告使用同一报告根目录和清理规则。

## 已确认行为

- 不使用 Codex 自动化、cron、`launchd` 或开机自启。
- 用户需要时手动启动调度器，机器重启后由人重新启动。
- 启动后先清理过期导出，再立即执行一次查询。
- 后续按照 IST 每小时的 `:00`、`:20`、`:40` 运行。
- IST 00:00 的周期先清理过期导出，再运行当天第一次查询。
- 不补跑进程停止期间错过的查询。
- 一次查询超过 20 分钟时不并发启动第二次；完成后等待下一个未来时间点。
- 查询返回 `partial` 或渠道错误时，保留已经生成的报告并继续调度。
- 意外程序级异常记录到标准错误，调度器继续等待下一周期；`KeyboardInterrupt`/`SIGTERM` 正常退出。
- 进程锁防止同一个项目同时运行两个调度器。

## 架构

### 手动查询入口

`wallet_quota.py` 继续提供现有 CLI。为了让调度器复用完整查询流程，提取一个返回退出码的现有 `main()` 调用边界，不复制登录、Provider、聚合或报告代码。

调度器每轮直接调用 `wallet_quota.main()`，传入相同的 `.env`、输出目录和 `--verbose` 选项。返回码 `0` 表示完整成功，`3` 表示已生成部分报告；两者都属于已完成周期。返回码 `1/2` 记录错误但不终止调度器。

### 常驻调度器

新增 `wallet_quota_scheduler.py`：

- CLI 参数：`--env-file`、`--output-dir`、`--verbose`，语义与手动入口一致。
- 启动时解析配置以确定唯一报告根目录。
- 在报告根目录旁创建非报告锁文件，例如 `.wallet_quota_scheduler.lock`，使用 macOS/Linux 标准库 `fcntl.flock(..., LOCK_EX | LOCK_NB)` 持有整个进程生命周期。
- 已有调度器持锁时，新进程打印安全错误并以非零码退出。
- 使用时区感知的 IST 时钟，不依赖电脑系统时区。Python 3.9 环境使用标准库 `zoneinfo.ZoneInfo("Asia/Kolkata")`。
- 计算下一个严格晚于当前时间的 `:00/:20/:40` 时间点；不会因上轮耗时而立即补跑历史时间点。
- 等待使用可中断的短时睡眠，避免一次超长 `sleep` 阻碍 `Ctrl+C`。

### 报告归属标记

新生成的 `aggregate.json` 在顶层 `metadata` 增加：

```json
{
  "generator": "walletQuota",
  "schema_version": 1
}
```

标记不包含凭据。手动和定时查询都通过同一报告写入器生成，因此都有相同标记。

## 安全清理

清理函数只接收已解析的报告根目录和当前 IST 日期。它不接受任意 glob 或 shell 命令，不跟随符号链接，不递归扫描报告根目录之外。

候选项必须同时满足：

1. 是报告根目录的直接子目录，不是文件或符号链接。
2. 名称符合 walletQuota 当前快照格式：`YYYYMMDD_HHMMSS`，可带从 `_2` 开始的数字后缀（包括 `_10` 及以后）。
3. 目录内存在普通文件 `aggregate.json`，且该文件不是符号链接。
4. JSON 可解析，顶层 `metadata.finished_at` 是带时区的 ISO 8601 时间。
5. 新报告必须包含 `generator == "walletQuota"` 和 `schema_version == 1`。
6. `finished_at` 换算成 IST 后的日期早于当前 IST 日期。

满足全部条件才删除整个候选目录。当天和未来日期报告永不删除；无效、损坏、无标记或结构不明的目录保留并产生安全警告。

### 旧报告兼容

当前仓库中已有 walletQuota 旧报告尚无 `generator` 标记。为满足“只删除本工具导出的数据”并能在升级后清理旧报告，旧目录仅在以下更严格条件下视为 walletQuota 导出：

- 目录名符合快照格式；
- `aggregate.json` 的顶层键恰好包含 `metadata`、`total`、`channels`；
- `metadata` 至少包含 `status`、`started_at`、`finished_at`、`provider_count`；
- 每个渠道对象包含 `status`、`complete`、`summary`、`metadata`、`orders`；
- 文件中不存在认证字段名；
- `finished_at` 的 IST 日期早于当天。

该兼容识别只用于报告根目录的直接子目录，不会扫描或删除其他位置。新版本之后一律优先使用明确生成标记。

删除使用 Python `shutil.rmtree`，目标必须先通过路径解析检查：候选父目录解析后等于报告根目录解析路径，候选本身不是符号链接。单个目录删除失败不会阻止检查其他候选，失败信息不包含账户或报告内容。

## 数据流

启动：

1. 读取 `.env` 和 CLI 覆盖，得到报告根目录。
2. 获取独占进程锁。
3. 使用当前 IST 日期清理过期导出。
4. 调用现有查询入口并保存一次报告。
5. 计算下一个 IST `:00/:20/:40` 时间点并等待。

周期：

1. 到达计划时间后重新读取当前 IST 日期。
2. 如果日期已经变化，清理所有早于当前日期的导出报告。
3. 执行一次查询。
4. 无论查询结果如何，计算下一个未来时间点。

重新启动时重复启动流程，因此能清理停机期间遗留的过期报告，但不会补跑查询。

## 日志与退出

标准输出显示：

- 调度器启动和下次运行的 IST 时间。
- 每轮查询现有安全终端摘要与报告路径。
- 清理成功的目录数量，不打印报告内容或账户值。

标准错误显示：

- 配置错误、锁冲突、单轮程序级错误和保留的异常候选目录。
- 不输出密码、Token、Cookie、签名、原始响应或完整账户。

退出规则：

- `Ctrl+C`、`SIGTERM`：释放锁并退出 `0`。
- 启动配置错误或锁冲突：退出非零。
- 单轮查询 `partial`：不退出常驻进程。

## 测试策略

所有自动化测试使用临时时钟、临时目录和 fake 查询函数，不访问真实支付接口，不真的等待 20 分钟。

- 时点计算：`12:00` 后为 `12:20`，`12:19:59` 后为 `12:20`，`12:40` 后为 `13:00`，23:40 后跨日到 00:00。
- 启动顺序：先清理、后立即查询。
- 周期顺序：跨 IST 日期时先清理、后查询。
- 慢查询：不补跑、不并发，等待下一个未来时间点。
- 退出码：查询 `0/3/1/2` 都不会错误终止循环；启动配置错误除外。
- 锁：第二个实例被拒绝，锁释放后可重新获取。
- 新报告：写入明确生成标记。
- 清理：只删除早于当天的有效新/旧 walletQuota 目录。
- 清理保护：当天、未来、普通文件、符号链接、嵌套目录、损坏 JSON、未知结构、伪造名称和报告根目录外目标都保留。
- 手动入口：既有 CLI 测试继续通过，证明手动查询未被移除。

## 完成标准

- `python3 wallet_quota_scheduler.py --verbose` 启动一个人工管理的常驻进程。
- 启动立即查询，之后按 IST `:00/:20/:40` 查询并保存。
- 日期切换后只删除 walletQuota 导出的过期报告，包括手动与自动报告。
- 任何清理路径都无法删除 `.env`、源码、Git 数据或报告根目录之外的数据。
- 手动命令 `python3 wallet_quota.py --verbose` 保持可用。
- 不使用 Codex、cron、`launchd` 或开机自启。
- 全部测试、编译、安全路径检查和代码审查通过。
